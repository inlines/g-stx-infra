# Unknown: региональные серийники

Отдельный дашборд **Game StockX - Unknown серийники**, UID `gstx-unknown-serials`.
Главный экран: текущие остатки, график истории, изменение за 7 и 30 дней. Таблица по датам и знаменатели находятся в сворачиваемом разделе. Фильтры платформ и регионов поддерживают множественный выбор. Существующий API-дашборд разбит на разделы без изменения запросов панелей.

## Определение

Числитель — количество уникальных игр на платформе без серийника в выбранной группе регионов. Знаменатель — все подходящие игры с релизом в этой группе; обе цифры используют одинаковые фильтры.

- PAL = Europe, USA = North America, JAP = Japan, OTHER = остальные регионы, включая Worldwide и пустой регион, как в каталоге.
- Есть точный региональный релиз: используются только серийники этого региона. Пустой точный релиз не закрывается серийником Worldwide или другой страны.
- Нет точного региона, но есть Worldwide: используется Worldwide, как на карточке каталога.
- Несколько релизов одной игры в регионе считаются одной игрой. Если хотя бы один подходящий релиз имеет серийник, игра в этой группе идентифицирована.
- При нескольких выбранных регионах игра попадает в Unknown, если не идентифицирована хотя бы в одном из них. В общем списке каждая игра один раз.
- Сохраняются существующие правила видимости: недigital_only на уровне игры/платформы, допустимый тип игры, датированный неотменённый релиз на платформе. PS1 учитывает физическое исключение для DLC/сборников. Будущие даты сейчас не исключаются самим каталогом — мониторинг повторяет это поведение.
- PC скрыт, как в переключателе платформ сайта. Остальные платформы выбираются по `platforms.active`, включая Saturn.
- Метрики соответствуют обновлённому интерфейсу при стандартных фильтрах. Поиск, жанр, мультиплеер и «показывать невышедшие» на сайте могут изменить результат.

`gstx_unknown_games{platform,region}` — числители; `gstx_region_games{platform,region}` — знаменатели. `gstx_unknown_platform_games` — уникальные игры с хотя бы одним региональным пропуском. Нельзя суммировать региональные столбцы и называть результат уникальными играми.

## Установка на VPS после доставки изменений

Сначала обновить backend и frontend с исправлением регионального Unknown, затем в `/root/g-stx-infra`:

```sh
bash scripts/setup-unknown-monitoring.sh
```

Нужны Python 3, systemd и Docker Compose. Установщик сначала проверяет запрос и JSON, потом устанавливает службу и таймер. Используются существующий textfile exporter `igdb-metrics`, его каталог `/var/lib/game-stockx-igdb/metrics` и datasource Prometheus. БД и сайт не перезапускаются. Grafana перезапускается для загрузки YAML-провайдеров из provisioning/dashboards; её том сохраняется. Для увеличения retention пересоздаётся только контейнер Prometheus, с сохранением того же тома /prometheus. Установщик проверяет путь тома до и после; при отсутствии постоянного тома останавливается. Краткий перерыв сбора метрик возможен. Файлы дашбордов существующий provider перечитает автоматически примерно за 30 секунд.

Сбор раз в 5 минут отдельным systemd timer, **не IGDB-кроном**. SQL — read-only, snapshot одной транзакции, timeout 20 секунд, lock timeout 2 секунды. Перекрывающиеся запуски исключены. Файл метрик заменяется атомарно. При ошибке предыдущий снимок остаётся, но статус ошибки и устаревшие данные явно видны; никакие ошибки не превращаются в нули.

История начинается после установки. По умолчанию retention увеличен до 90 дней, лимит блоков TSDB — 2 GB (WAL/head требуют дополнительного места). Настройки можно переопределить в .env через PROMETHEUS_RETENTION_TIME и PROMETHEUS_RETENTION_SIZE. Если первым достигнут лимит размера, история будет короче. Данные прежнего тома сохраняются; docker compose down и --renew-anon-volumes использовать нельзя. Сравнение за неделю/30 дней появится после накопления соответствующего периода. Уменьшение остатка — не обязательно число найденных кодов: на него влияют импорты, удаления и digital_only.

## Проверка

```sh
systemctl status gstx-unknown-metrics.timer
journalctl -u gstx-unknown-metrics.service -n 20 --no-pager
cat /var/lib/game-stockx-igdb/metrics/unknown-status.prom
```

В Grafana откройте новый дашборд, выберите платформу и регион. В интерфейсе Unknown выберите то же без дополнительных фильтров. Через один цикл сбора числитель/знаменатель должны совпасть.

Проверка локально проведена на реальном PostgreSQL: граничные случаи, сравнение SQL API и сборщика, пропуски при ошибках, валидность всех PromQL, Grafana 12.3, 24 фронтенд-теста списка. Результаты конкретного прогона сохранены в пакете unknown-monitoring-20260921/validation.

## Отключение

```sh
systemctl disable --now gstx-unknown-metrics.timer
systemctl stop gstx-unknown-metrics.service
```

Исторические метрики останутся в Prometheus до истечения retention. После 15 минут без свежего снимка дашборд перестанет показывать старый остаток как актуальный. Файлы метрик и дашборды автоматически не удаляются.
